# 今日のごはん — 1週間の献立と買い物リスト

1週間分の献立を自動で組み、そこから買い物リストを作るスマホ向け Web アプリです。
家族で同じ献立・買い物リストを共有でき、だれかが変えるとほかの人の画面にもすぐ反映されます。

- ホーム画面に追加して、アプリのように使えます（PWA）。電波の弱い売り場でも、前に開いた買い物リストを表示できます。
- 料理に慣れていない人向けの「🌱 わかば」と、慣れた人向けの「🌾 みのり」の2段階で、レシピの難しさとコツの量を変えられます。

## できること

| 機能                   | 内容                                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 献立の自動作成         | 和・洋・中の割合、曜日ごとの予算・調理時間・副菜の有無・料理レベルに合わせて、1週間分（主菜・汁物・副菜）を作ります。直近に食べた料理や、前後の日と同じ主材料は出にくくします。1日・1品だけの作り直しや、曜日の入れ替えもできます。 |
| 買い物リスト           | 献立の材料を合算し（g/kg、大さじ/小さじ/カップ などの単位をそろえる）、売り場の順に並べます。調味料や米など家にあるものは除きます。手で追加した品、チェックの状態は家族で共有します。                                               |
| レシピ                 | 初期レシピ110品（主菜60・汁物25・副菜25）。自分のレシピの登録・編集、初期レシピの複製・非表示、料理名や材料名での検索ができます。材料は「A（たれ）」「B」のようにグループに分けられ、同じ調味料でもグループごとに別々に表示します。 |
| 写真・URL から取り込み | レシピの写真やレシピサイトの URL から、材料・手順・料理レベル・和洋中・主菜/汁物/副菜を自動で読み取って下書きにします（Workers AI）。                                                                                               |
| 料理レベル             | 🌱 わかば：手順5つ以内・揚げ物なし・材料7品目以内のレシピだけを出し、手順ごとに「ひとことコツ」を表示します。ゆっくりモード（1手順ずつ大きく表示）とタイマー付き。                                                                  |
| 家族で共有             | 招待コード・招待リンクでグループに参加。オーナーとメンバーの役割、複数グループの切り替えに対応します。                                                                                                                              |
| リアルタイム同期       | 献立・買い物リスト・自炊記録などの変更を、同じグループのメンバーにすぐ届けます。ほかの人が献立を変えると「◯◯さんが水曜の主菜を変更しました」と知らせ、その日のカードを光らせます。                                                  |
| 自炊記録               | 作った料理を記録し、料理ごとに写真を残せます。                                                                                                                                                                                      |
| テーマ                 | パステル（いちごミルク・ピーチレモン・ラベンダーバナナ・さくら抹茶）と、ノワール（ミッドナイト・グラファイト・フォレスト・ボルドー）から選べます。                                                                                  |

## 技術構成

| 分野         | 使っているもの                                                                            |
| ------------ | ----------------------------------------------------------------------------------------- |
| 実行環境     | Cloudflare Workers（静的アセット配信 + API を1つの Worker で）                            |
| API          | Hono（RPC クライアントで画面側と型を共有）、Zod                                           |
| データベース | Cloudflare D1 + Drizzle ORM                                                               |
| 画像         | Cloudflare R2                                                                             |
| AI           | Workers AI（`@cf/mistralai/mistral-small-3.1-24b-instruct`、画像と文章の両方に対応）      |
| リアルタイム | Cloudflare Durable Objects（WebSocket Hibernation API）                                   |
| 認証         | Google OAuth 2.0（PKCE）を自前で実装、セッションは D1                                     |
| 画面         | React 19、Vite、TanStack Router / Query、Tailwind CSS v4、Motion                          |
| PWA          | vite-plugin-pwa（Workbox）                                                                |
| テスト       | Vitest + `@cloudflare/vitest-plugin`（D1・R2・Durable Objects を含めて workerd 上で実行） |

### Durable Objects を使う理由

家族のだれかが献立を変えたら、ほかのメンバーの画面にすぐ反映したい、という要件のために使っています。

- **グループごとに1つの部屋**：`GroupRoom` をグループ ID で1つずつ作り、そのグループの接続と通知をすべてそこに集めます。通知の順序がそろい、ほかのグループと混ざることもありません。
- **待っている間は眠る**：WebSocket Hibernation API を使うので、画面を開いたまま何も起きていない間は Durable Object がメモリから外れ、課金時間がほぼかかりません。家庭のアプリは「つながっているが静か」な時間が大半なので、この性質が合っています。
- **データの正本は D1**：Durable Object は「変わったよ」という通知を配るだけで、データは持ちません。通知を受けた画面が API から最新の内容を読み直すので、通知を取りこぼしても表示がずれません。切断中は 15 秒ごとの読み直しに切り替わります。
- **同時編集**：献立にはバージョン番号があり、ほかの人が先に変えていた場合は 409 を返して、最新の内容を読み直してから操作し直してもらいます。

### 献立作成のしくみ

`src/shared/planner` に純粋関数としてまとめています（シード付き乱数で、同じ条件なら同じ結果になるのでテストしやすい）。

1. 和洋中の割合から、1週間の主菜のジャンルの数を最大剰余法で決める
2. 候補ごとに重みを付けて選ぶ（1〜3週間以内に出た料理は出にくく、前後の日と同じ主材料はさらに出にくく、汁物・副菜は主菜と同じジャンルが出やすい）
3. 条件に合う候補がないときは、時間 → 予算 → ジャンル → 重複の順に条件をゆるめる（🌱 わかばの日は、わかばのレシピ以外は使わない）
4. 1週間の予算を超えたら、高い品を安い品に入れ替える

## セキュリティ

- **秘密情報はコミットしない**：ローカルは `.dev.vars`（`.gitignore` 済み）、本番は `wrangler secret put` で登録します。
- **セッション**：ランダムなトークンを `HttpOnly; Secure; SameSite=Lax` の Cookie に入れ、D1 には SHA-256 のハッシュだけを保存します（30日、使うたびに延長）。
- **CSRF**：`hono/csrf` で Origin を確認します。ログイン後の戻り先（`?next=`）は同じサイト内のパスだけを許可します。
- **グループの権限**：すべての API で「そのグループのメンバーか」を確認します。写真もメンバーしか見られません。
- **URL 取り込みの SSRF 対策**：http/https・ポート 80/443 だけを許可し、IP 直書きのプライベートアドレスや `localhost` などを拒否します。リダイレクトは毎回確認し最大3回、10秒・2MB で打ち切ります。Workers の `fetch` では DNS 解決後の IP を確認できないため、DNS リバインディングへの対策はホスト名の確認までです（Cloudflare のネットワークから利用者の内部ネットワークへは届きません）。
- **画像**：マジックバイトで種類を確かめ、5MB までに制限します。端末側で長辺 1600px の WebP に縮小してから送ります。
- **回数制限**：AI 取り込みは1人1日20回、写真のアップロードは1日60回、招待コードの入力は1時間20回まで。
- **オフライン用の保存**：ログアウトすると、端末に保存した API の応答と写真を消します。

## 開発

必要なもの：Node.js 20.19 以上、Cloudflare アカウント（Workers AI をローカルから使う場合）、Google Cloud の OAuth クライアント。

```bash
npm install
cp .dev.vars.example .dev.vars   # Google の Client ID / Secret を入れる
npm run db:migrate:local         # ローカルの D1 にテーブルを作る
npm run db:seed:local            # 初期レシピ110品を入れる
npm run dev                      # http://localhost:5173
```

- Google Cloud Console の OAuth クライアントに、リダイレクト URI `http://localhost:5173/api/auth/google/callback` を登録してください。
- Workers AI はローカルからもリモートで実行します（`npx wrangler login` が必要）。ログインせずに動かすときは `LOCAL_ONLY=1 npm run dev`（AI 取り込み以外は動きます）。

| コマンド                             | 内容                                                      |
| ------------------------------------ | --------------------------------------------------------- |
| `npm run dev`                        | 開発サーバー                                              |
| `npm test`                           | テスト（ユニット + workerd 上の API テスト）              |
| `npm run typecheck` / `npm run lint` | 型チェック / Lint                                         |
| `npm run build` / `npm run preview`  | 本番ビルド / ビルドしたものをローカルで確認               |
| `npm run db:generate`                | `src/worker/db/schema.ts` からマイグレーションを作る      |
| `npm run pwa:assets`                 | `scripts/build-icons.ts` からアプリアイコン一式を作り直す |
| `npm run seed:preview`               | 初期レシピを一覧できる HTML を作る                        |

```

  app/        画面（React）。routes/ がそのまま URL になる
  worker/     API（Hono）、DB スキーマ、AI、Durable Object

seed/         初期レシピ（短い記法で書いて SQL に変換）
migrations/   D1 のマイグレーション
test/         workerd 上で動かす API テスト
```
